git-subsync คือ Git extension สำหรับไฟล์ที่ไม่ควรอยู่ใน Git เช่น ไฟล์ export
จากงานดีไซน์ บรีฟ รูปภาพ หรืออะไรก็ตามที่ทีมเก็บไว้ใน Google Drive อยู่แล้ว
เราผูกโฟลเดอร์ใน repository เข้ากับโฟลเดอร์ใน Drive ได้คล้าย submodule แล้วใช้
`git subsync sync` ให้ทั้งสองฝั่งตรงกัน เมื่อติดตั้งแล้ว git จะเรียกใช้ได้ในชื่อ
`git subsync`

## เป้าหมาย

ไฟล์ binary ขนาดใหญ่ทำให้ repository บวม แต่ถ้าเก็บไว้แค่ใน Drive
โค้ดกับไฟล์ที่ใช้คู่กันก็จะค่อย ๆ ไม่ตรงกัน สิ่งที่อยากได้คือ:

- คำสั่งเดียวที่วางโฟลเดอร์ Drive ของโปรเจกต์ไว้ถูกที่หลัง clone
- ซิงก์สองทางเป็นค่าเริ่มต้น และมีโหมดดาวน์โหลดอย่างเดียวกับอัปโหลดอย่างเดียว
- Conflict ที่ไม่ทำให้งานของใครหาย
- ไฟล์ที่ซิงก์ไม่หลุดเข้าไปในประวัติของ Git เลย

## สิ่งที่สร้าง

| คำสั่ง                  | ทำอะไรได้                                                                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| add                     | ผูก path เข้ากับโฟลเดอร์ Drive จากลิงก์แชร์ บันทึกลงไฟล์ `.gitsubsync` ที่ commit ไว้ เพิ่ม path ลง `.gitignore` แล้วซิงก์ครั้งแรก |
| sync                    | ซิงก์ทุกโฟลเดอร์ที่ผูกไว้หรือเฉพาะที่ระบุ มี `--dry-run` และโอนไฟล์พร้อมกันได้สูงสุด 32 ไฟล์                                       |
| list                    | แสดงโหมด ชื่อโฟลเดอร์ Drive และเวลาซิงก์ล่าสุดของแต่ละโฟลเดอร์ ใช้ได้แม้ออฟไลน์                                                    |
| remove                  | ยกเลิกการผูกโฟลเดอร์ โดยเก็บไฟล์ในเครื่องไว้และไม่แตะ Drive เลย                                                                    |
| login / whoami / logout | ล็อกอินด้วย Google ผ่านเบราว์เซอร์ ดูบัญชีที่ใช้อยู่ และเพิกถอน token                                                              |

## การทำงาน

- **Checksum สามตัวตัดสินทุกไฟล์** ทุกครั้งที่ซิงก์ จะเทียบ MD5 ของไฟล์ในเครื่อง
  ไฟล์บน Drive และเวอร์ชันที่บันทึกไว้ตอนซิงก์ครั้งก่อน แล้วให้ planner
  ซึ่งเขียนเป็น pure function แปลงผลเป็นดาวน์โหลด อัปโหลด บันทึก ข้าม หรือ
  conflict ตามแต่ละโหมดทั้งสาม โดยมีเทสต์ครอบทุกแถวของตารางนี้
- **Conflict เก็บไว้ทั้งสองเวอร์ชัน** ถ้าไฟล์ถูกแก้ทั้งสองฝั่ง
  เวอร์ชันหนึ่งจะถูกเก็บเป็น `name_copy_<timestamp>` ส่วนโหมดอัปโหลดจะไม่เขียนทับ
  Drive เลย แต่จะรายงานว่าใครแก้ไฟล์และแก้เมื่อไร แล้วจบด้วย exit code 2
  จนกว่าจะแก้ conflict
- **ทุกการเขียนไฟล์ถูกตรวจ** ไฟล์ที่ดาวน์โหลดจะเขียนลงไฟล์ชั่วคราวก่อน ตรวจกับ
  MD5 ของ Drive แล้วจึง rename เข้าที่
  ไฟล์ที่อัปโหลดจะกลายเป็นเวอร์ชันใหม่ของไฟล์เดิมบน Drive ลิงก์แชร์จึงยังใช้ได้
  ไฟล์ที่ใหญ่กว่า 8 MiB ใช้ resumable upload และก่อนเขียนทับฝั่งไหนก็ตาม
  จะตรวจก่อนว่าไฟล์ไม่ได้เปลี่ยนไปหลังสแกน
- **ซิงก์ที่ถูกขัดจังหวะทำต่อจากเดิมได้** state ถูกบันทึกเมื่อแต่ละไฟล์โอนเสร็จ
  รวมถึงตอนกด Ctrl-C และมี lock file กันไม่ให้ซิงก์โฟลเดอร์เดียวกันพร้อมกันสองครั้ง
  ส่วน rate limit และ error ฝั่งเซิร์ฟเวอร์จะลองใหม่แบบ exponential backoff
- **ไฟล์ที่ commit ไว้ถูกใช้เล่นงานเราไม่ได้** `.gitsubsync` ติดไปกับ repository
  จึงบังคับให้ path อยู่ใน repo และห้ามผ่าน symbolic link
  อีกทั้งการซิงก์ครั้งแรกของโฟลเดอร์ที่มีไฟล์อยู่แล้วจะถามก่อนอัปโหลด การ pull
  จึงแอบผูกไฟล์ของเราเข้ากับโฟลเดอร์ Drive ของคนอื่นไม่ได้
- **ล็อกอินด้วย OAuth แบบ loopback พร้อม PKCE** เซิร์ฟเวอร์ชั่วคราวบน `127.0.0.1`
  รับ redirect จาก Google ตรวจค่า `state` และรับแค่ callback แรก token
  เก็บด้วยสิทธิ์ `0600` และ token ที่ refresh แล้วจะถูกบันทึกกลับลงไฟล์

## Stack

เขียนด้วย Go ใช้ Cobra ทำคำสั่ง และใช้ Drive API client ตัวทางการของ Google
โดยมีแค่แพ็กเกจ CLI ที่ import Cobra ทุกครั้งที่ push tag ใหม่ GoReleaser กับ
GitHub Actions จะ build binary สำหรับ macOS และ Linux ทั้ง amd64 และ arm64
สร้าง GitHub Release และอัปเดต Homebrew cask ใน tap ของตัวเอง ส่วน CI รัน
`go vet`, `go test -race` และ build บน Ubuntu และ macOS
